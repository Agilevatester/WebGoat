⚠️ Real-World Context:

In CVE-2021-44228, the vulnerability exists because Log4j automatically processes special lookup syntax in ANY user-supplied data that gets logged—whether it comes from parameters, headers, cookies, or any other input source. By injecting patterns into HTTP request headers, you can trigger JNDI lookups that the logging library will execute.
