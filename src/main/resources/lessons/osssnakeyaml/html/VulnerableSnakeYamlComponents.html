Challenge 1: Configuration Import Service

A configuration management service accepts documents in multiple formats and imports them into the application's runtime configuration store. The service supports several import strategies with different type-handling policies.

The primary import endpoint uses a full constructor. Explore what happens when the document body contains type directives beyond standard scalars and mappings.

Challenge 2: Schema-Validation Import

A second import path uses loadAs to enforce a target type during deserialization. Explore whether type tags in the document body can influence the deserialization outcome on this path.

Challenge 3: Safe Import (Mitigation A)

This path applies a restrictive constructor that rejects arbitrary type instantiation. Try to achieve the same outcome as in Challenges 1 and 2 and observe how this policy changes the behaviour.

Challenge 4: Restricted Import (Mitigation B)

This path uses a type-allowlist constructor that permits only java.util.List and java.util.Map. Try to achieve the same outcome again and observe the difference.

Configuration Preview (Dry Run)

Use this endpoint to preview how many top-level keys a document contains before committing an import. The preview path uses a safe parser and does not persist any data.
