🔍 Craft Your XSLT Policy:

💡 Hints to explore:

  • XSLT Namespaces: Special XML namespaces can extend XSLT capabilities
  • Java Access: Xalan allows accessing Java classes through namespace URIs
  • Runtime Execution: Can you invoke java.lang.Runtime methods?
  • Namespace Syntax: Try xmlns:rt="http://xml.apache.org/xalan/java/java.lang.Runtime"
  • Enable XSLT: Check the isXsl parameter to process your policy as XSLT

ℹ️ What to Look For:

  • ✓ XSLT stylesheet declarations
  • ✓ Java namespace extensions in XSLT
  • ✓ Method invocations on Java classes
  • ✓ Runtime command execution patterns

⚠️ Real-World Context:

In CVE-2024-28109, the vulnerability exists because VeraPDF processes user-supplied XSLT policies without restricting dangerous namespace declarations. XSLT, combined with Xalan's Java namespace extensions, allows direct invocation of Java methods including Runtime.exec(). This transforms a simple policy processor into a code execution engine.
